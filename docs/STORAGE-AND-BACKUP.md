# 保存先とバックアップ

以下は説明用の配置例です。既存のデータがある環境で、コピーして上書き・削除するためのコマンドではありません。

| 置き場所の例 | 保存するもの |
|---|---|
| `/opt/immich` | Compose、設定、運用用の資料 |
| `/srv/immich-db/postgres` | 内蔵SSD上のPostgreSQL実データ |
| `/mnt/photos/immich` | 外付けSSD上の写真・動画・関連ファイル |
| 別PCのバックアップ用ディスク | 原本、DBダンプ、構成資料、検証用の一覧 |

この例のパスは公開説明用に置き換えています。実環境で使う値は公開しません。

## 何を保存するか

Immich公式は写真・動画とデータベースの両方のバックアップを案内しています。DBダンプには写真・動画の実体は入っていません。
[公式バックアップ手順](https://docs.immich.app/administration/backup-and-restore/)

参考運用の記録は以下の方式です。今回の公開準備で再実行した結果ではありません。

- サーバー側でDBダンプを定期保存。
- 別のWindows PCが読み取り専用の接続で原本とDBダンプを取得。
- コピー後にハッシュで照合し、全体成功のときだけ成功状態を記録。
- 大量の追加・変更・削除が見えた場合に停止し、人が内容を確認。
- 同期元で消えたものを、そのままバックアップ側から自動削除しない運用。

## 復元の設計

原本、DBダンプ、採用バージョン、設定の組合せを記録します。PostgreSQLのデータディレクトリを稼働中に単純コピーする方法を、整合性のあるDBダンプと同じものとして扱わないでください。

復元試験は本番とは別の保存先・接続先・コンテナで行う計画とし、確認後に手順を公開します。既存DBを消す復元コマンドはこの資料に載せていません。

別ディスクへのコピーだけで3-2-1バックアップを満たすとは限りません。オフラインまたは遠隔の追加コピーの有無と復元試験を確認します。
